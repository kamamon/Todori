# 業種カタログの書き方（会社経営モード）

ブラウザゲーム「頭取」の会社経営モードで、プレイヤーが選べる業種（いまは約5,000種類）を、ここに書く決まりで足していく。
業種は `src/20c_cat_*.js` にデータとして書く。ゲームのエンジンは9つの「事業の型」(`eng`) を持ち、
業種ごとのパラメータ (`p`) と設備 (`eq` / `aux`) で動きが変わる。開始時にエンジンが利益率を自動で
調整（キャリブレーション）するので、数字は「実在の中小〜中堅企業として自然な規模と比率」を目安にすればよい。

設備・工事の型・季節の型・大分類のキーは `src/20a_ks_equip.js` にある（`KS_EQ`, `KS_PROJ_LIB`, `KS_SEASONS`, `KS_SECTORS`）。
**そこにないキーは使わない。** 合う設備がないときは汎用キーに名前を付ける（下の「設備の書き方」）。

## ファイルの形

```js
'use strict';
/* 20c_cat_xxx.js : 業種カタログ（○○業） */
KS_CAT_ADD([
  {
    sec: 'E',                  // 大分類（KS_SECTORS のキー：A B C D E F G H I I2 J K L M M2 N O P R）
    grp: '金属製品製造業',      // グループ名（中分類・小分類にあたる見出し）
    eng: 'mfg',                // 事業の型：shop rest mfg build trade pro subs cap trans
    bm: 'mfg',                 // 銀行が比べる業界平均：mfg con whl ret food trn re it med htl agr
    icon: '金',                // 1文字の漢字（グループの印）
    season: 'mfg',             // 季節の型（KS_SEASONS のキー）。省略は flat
    d: '金属の板を切る・曲げる・溶接して部品をつくる。',  // グループの説明（1〜2文）
    how: '図面どおりの部品を少量ずつ受注し、納めて翌月か翌々月に入金。単価は加工の時間と材料で決まる。', // 売上の立ち方（25〜100字）
    kf: '機械の稼働率と段取りの早さ、見積の正確さ、取引先の数。',   // 成功のカギ（25〜100字）
    risk: '主な取引先の発注の減少、鋼材の値上がり、機械の故障と労災。', // 主なリスク（25〜100字）
    kw: ['板金', 'レーザー加工', '溶接'],                         // 探すときの言葉（言い換え・略語。省略可）
    prod: ['板金部品', '筐体', '架台'],                   // 主な製品・サービス（2〜5個）
    cust: ['機械メーカー', '電機メーカー'],               // 主なお客（2〜4個）
    p: { mode: 'job', price: 6500, mat: 2800, base: 2000 }, // 事業の型ごとのパラメータ（下の表）
    eq: ['laser_fiber:1', 'pb:3', 'weld_tig:4'],          // 主な設備（型ごとの意味は下）
    aux: ['forklift:2', 'compressor:1'],                  // 補助の設備（mfg のみ。省略可）
    laws: ['machine', 'chem'],                            // 業種に関わる法令のキー（下の表）
    lic: { n: '…の許可', law: '…法', every: 5 },          // 許認可（あれば。every は更新の年数、更新がなければ 0）
    items: [
      '板金加工業',                                          // 文字列だけ＝グループの設定をそのまま使う
      ['精密板金加工業', { d: '…', p: { price: 7500 }, eq: ['laser_fiber:2', 'bend_robot:1', 'weld_laser:1'], aux: ['cmm:1'] }],
      // [名前, 上書き]。上書きできるキー：d prod cust p eq aux laws lic season icon scale bm how kf risk kw
      //   p は項目ごとに「マージ」、ほかは「置き換え」
    ],
  },
]);
```

- 業種名は**カタログ全体で一意**にする（他のファイルと重ならないよう、名前は具体的に。例：「金属プレス製品製造業（自動車部品）」）。
- 日本標準産業分類の細分類のような、実在する業種の名前にする。業態・規模・得意分野の違い（「LCC」「地域航空」「貨物航空」など）で分けてよいが、中身のない水増しはしない。
- 項目ごとに `p` や `eq` を変えて、同じグループの中でも数字と設備に違いを出す（少なくとも半分以上の項目に何かの上書きを付ける）。
- 会社の大きさは `p` の数字（店の数・設備の数・人数など）で決まる。`scale` は大きな業種の目印として残しているが、いまのエンジンは使わない。
  大きな設備が要る業種（航空・海運・鉄道・発電・通信キャリア・製鉄など）でも、
  ゲームの「中小〜中堅の会社」として成り立つ最小限の規模にする（例：ターボプロップ機3機の地域航空、内航船2隻の海運会社）。
- `how`・`kf`・`risk` は、業種を選ぶ画面の「くわしく」に出る補足。グループに書けば全項目に効き、項目で上書きもできる。
  どの業種にも説明（`d`）と、この3つがあるようにする（`node test/check_search.js` で確かめる）。
- 取引先の数（trade の `custN`）を大きくしすぎると、会社をつくる計算が遅くなる。400以下を目安に。

## 設備の書き方

`'キー:台数'` または `'キー:台数:名前'`（名前を変える。例 `'line:2:製氷設備'`、`'gpu:8:推論用GPUサーバー'`）。
汎用キー：mfg の量産ライン `line`、農地など `field`。施設は `KS_EQ` の cap 系、利用者を支える設備は subs 系。

## 事業の型とパラメータ（p）

数字は円・人・月。省略したキーは既定値。

### mfg（ものづくり）
`mode` が `'job'`（受注加工：能力＝機械の加工時間）か `'line'`（量産：能力＝ラインの生産量）。農業・漁業・林業・鉱業も `line`。

| キー | job（受注加工） | line（量産・農林水産） |
|---|---|---|
| mode | 'job' | 'line' |
| unit | （不要：時間） | 製品の単位 '個' 'トン' 'kL' '台' '着' '枚' '本' '箱' '食' '頭' 'kg' など |
| price | 加工賃（1時間・円）。既定6000 | 1単位の販売価格（円） |
| mat | 1時間あたりの材料費。既定3200 | 1単位の材料費（円） |
| base | 月の注文（加工時間）。既定2150 | 月の注文（単位の数） |
| lineCap | — | ライン1つの月の生産能力（単位） |
| lineCost | — | ライン1つの価格（円） |
| lineLab | — | ライン1つに要る作業者（人）。既定8 |
| energy | 1時間あたりの電力・工具費。既定300 | 1単位あたりの光熱費 |
| terms | 売掛金の入金まで（月）。既定2 | 同じ |
| matDays / fgDays | 材料の在庫日数20 | 製品の在庫日数10 |
| office | 営業・事務の人数。既定4 | 同じ |
| wage | 作業者の月給。既定30万 | 同じ |
| bldg / land | 工場の建物・土地の額。既定1.2億・6000万 | 同じ |
| rn | 職種名 [作業者, 営業・事務] | |

- job の `eq` は加工機（KS_EQ の `k:'job'`）。能力は月の注文の1.1〜1.3倍くらいになるようにする（例：base 2,150時間なら機械10台×220時間）。
- line の `eq` はライン（`k:'line'`）。`lineCap × ラインの数` が `base` の1.1〜1.4倍になるようにする。
- `aux` は補助設備（`k:'aux'`：検査・ロボット・フォークリフト・農機など）。

### subs（会員・利用者から稼ぐ）
| キー | 意味 | 既定 |
|---|---|---|
| users | 開始時の利用者（契約・部数・会員・回線） | 20000 |
| arpu | 1人の月額（円） | 1500 |
| ad | 1人あたりの月の広告収入 | 0 |
| gmv / take | 1人の月の取扱高と手数料率（プラットフォーム） | 0 / 0 |
| churn | 月の解約率 | 0.02 |
| cac | 1人を獲得する費用 | 5000 |
| cpu | 1人あたりの月の変動費（サーバー・用紙・配達・通信・GPU） | 300 |
| fixed | 月の固定の運営費（番組・記事・コンテンツの制作など） | 1000万 |
| capPer | 能力の設備1台で支えられる利用者 | 5000 |
| dev / devWage | 開発・制作の人数と月給 | 10 / 45万 |
| ops | 運用・営業の人数 | 5 |
| trend | 市場の年の伸び（新聞-0.05、生成AI 0.35） | 0.03 |
| b2b | 法人向け（請求書で翌月入金） | false |
| rn | 職種名 [開発・制作, 運用・営業] | |
`eq` は利用者を支える設備（`server` `gpu` `bs_macro` `ftth` `rotary_press` `studio` `transmitter` `gym_set` `school_bldg` など）。
例：新聞社 → users 部数、arpu 購読料、ad 広告、cpu 用紙・印刷・配達、eq 輪転機。携帯キャリア → users 回線、eq 基地局。
放送局 → users 視聴世帯、arpu 0、ad 大きい、fixed 番組制作費。学習塾・フィットネス → users 生徒・会員、eq 校舎・ジム。

| units | 開始時の能力 | 100 |

| var | 稼働1単位あたりの月の変動費（清掃・電力・食材など） | 価格の15% |

| ar | 後払いで入る売上の割合 / terms 何か月後 | 0.5 / 1 |
| kwh | 1単位の月の電力量（DCのラックなど） | 0 |

| rn | 職種名 | |

## 法令のキー（laws）
machine（機械の安全）・fall（墜落防止）・chem（化学物質）・haccp（食品衛生）・alcohol（社用車のアルコールチェック）・
kyoka（建設業許可）・privacy（個人情報）・kiken（危険物）・rad（放射線業務の被ばく管理）・export（輸出管理：軍事にも使える製品・技術）。
労働時間・健康診断・消防などは自動で全業種にかかる。
業種独自の許認可は `lic`（例：`{ n: '一般貨物自動車運送事業の許可', law: '貨物自動車運送事業法', every: 0 }`、
`{ n: '旅館業の許可', law: '旅館業法', every: 0 }`、`{ n: '酒類販売業免許', law: '酒税法', every: 0 }`、
`{ n: '産業廃棄物収集運搬業の許可', law: '廃棄物処理法', every: 5 }`）。

## 発電（cap で per: 'mwh'）の数字
units は出力（MW）、price は1MWhあたりの売値、occ は設備の利用率、var は1MWhあたりの燃料費などの変動費。
fuel を書くと変動費を燃料費に計上する（'oil' なら原油の値段につれて動く。'bio'・'nuke' は動かない）。
levy は1MWhあたりの拠出金など、om は1MWあたり月の運転・保守の委託費、capPay は1MWあたり月の基本料金（発電しなくても入る）。
nuke: true の原子力は、13か月ごとに2か月の定期検査で止まり、まれに規制・裁判で長く止まる。

## どの事業の型にも書ける p のキー
- accF：労災の起きやすさの倍率（既定 1。安全管理の仕組みが特に厚い原子力などは 0.15〜0.3）。
- accSet：労災の文の組。'plant' は発電所・タンク基地・射場などのプラント向け（足場からの転落、分解点検での挟まれ など）。

## 季節の型（season）
flat retail food mfg con whl it fiscal summer winter gift toy fashion tourism travel hotel ski beach leisure school
moving wedding funeral car medical rice veg fruit fish solar power cold news yearend

## 品質の目安
- 実在の業種名・設備・お客・製品を使う。日本の中小〜中堅企業のリアルな姿に。
- 同じグループの中でも、単価・規模・設備・原価率を項目ごとに変える。
- 説明 `d` は「何をして、何で稼ぐか、何が難しいか」を1〜2文で。
- すべての値はゲーム内の通貨（円）。1億＝1e8、1万＝1e4 の書き方でよい。

## 確かめ方
- `node test/check_catalog.js`：業種名の重複、キー・設備・季節の誤りを調べる。
- `node test/check_search.js`：どの業種も名前で探すと先頭に出るか、ひらがなで探しても見つかるか、説明と補足（how・kf・risk）があるかを調べる。
- `node test/check_capacity.js`：ものづくり（mfg）の業種で、設備の能力（`lineCap × ラインの数`、加工機の能力）が `base` の1.1〜4倍に入っているかを調べる。
- `node test/sweep_catalog.js 1 0 --eng=mfg`：業種を1つずつ会社にして、過去4期とその後2年をボットで経営し、倒産・極端な利益率・1人あたり売上が極端な業種を一覧にする。
- 開始時のキャリブレーションは、会社の写しで事業を1年ほど動かして営業利益率を測り、基準の単価（卸売は取引先の規模、建設は工事1件の金額）を合わせる。倍率（`calK`）が0.4より小さい・2.5より大きい業種は、カタログの数字（単価・原価・人数・規模）を見直す。
- グループの許認可を項目で外すときは `lic: null` と書く。
